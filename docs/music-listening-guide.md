# Soundtrack listening guide

Each row gives you a place or situation to picture while judging the instrumental
(Sampled) palette, plus a specific question about whether the new timbres fit.
The same context applies to the DS and Chip alternatives; all three are now
available through the provisional [live instrument pack](music-live.md).
Later locations and boss names appear below.

**Ready to hear: Asuka City (BGM001, sequence 000).**
Picture returning to the starting town between excursions. The current sampled
arrangement uses piano, reeds, bass, strings, and drums. The useful first decision
is whether this feels welcoming and recognizably digital, or too much like a lounge.

- [Instrumental / Sampled audition](../output/music-audition-02/soundfont/preview.wav)
- [DS-inspired audition](../output/music-audition-ds-final/preview.wav)
- [Chip audition](../output/music-audition-02/chip/preview.wav)

These audio links are local build outputs and will not work on a fresh clone.
Only Asuka City's three arrangements are authored so far. The other rows describe
future offline auditions, not audio already rendered. A separate
[live instrument pack](music-live.md) now covers 42 banks through SETTINGS,
using provisional sample-level arrangements you can judge in the game. These
are not identical to the offline previews. See [rendering instructions](music-palettes.md).

## Reading the labels

**41 complete sequence bodies match uniquely** to the community-tagged
[PSF collection](https://www.zophar.net/music/playstation-psf/digimon-world-3).
That establishes which disc sequence received each name. It does **not** establish
every room, server variant, or story override where the game plays it. No row has
been promoted to runtime-confirmed scene usage by this audit. Names are community
labels, not an official soundtrack tracklist.

Short scene descriptions use the matched labels and, where needed, the locations
described in [EmeraldPhoenix's walkthrough](https://gamefaqs.gamespot.com/ps/562323-digimon-world-3/faqs/18310).
The mood suggestions and listening questions are our own proposed arrangement
goals for you to accept or change; they are not statements of the composer's intent.

The ID means **bank : sequence**, with sequence IDs zero-based. For example,
Training Gym is `BGM031:002` and Card Battle is `CBTL00:004`. Soundtrack album
numbers do not correspond to disc filenames. One bank can contain music plus
very short control/cue sequences.

## Still unidentified or outside this pass

- `TTLBGM:000` exports successfully but has no complete sequence match in the
  reference. Its filename suggests title-related use only; that is unconfirmed.
- The reference's **Auction Theme** has no complete match in this audited set.
  Do not assign it to the title bank by elimination.
- `MPCOMMON` contains multiple SEP/VAB entries, including substantial sequences
  with no complete reference match. Its sequence numbers repeat across entries,
  so a future identifier must also include the pack-entry index. These are not
  yet named songs or authored auditions.
- Environmental packs, streamed movie audio, victory/game-over uses, and all
  alternate room/server uses are not covered by this guide. This is not a claim
  to have catalogued every sound in the game.

## How to give feedback

Use the track name or ID and a short description, for example:
**“Asuka / Sampled: reeds too nasal, piano good, make the backing less lush.”**
Useful judgments are scene fit, lead character, rhythmic weight, how tiring the
loop becomes, and whether a cue still has its own identity beside adjacent tracks.
There is no need to name a particular instrument or supply a GM program number.

Every future preview includes a `listening-notes.md` beside its WAV, selected by
the actual exported MIDI hash. Known tracks also carry their context in
`preview.json`; unknown MIDI stays explicitly unidentified.

## Evidence and reproduction notes

[The metadata catalog](../assets/music/track-locations.json) records source MP,
sequence-body, and exported-MIDI SHA-256 hashes, the reference archive hash,
matching PSF filename, and byte offset in the decompressed executable. The audit
read PSF headers, decompressed their zlib payloads, and searched for each complete
original SEP event body. It never executed reference code. Only metadata and
original listening notes belong in Git; disc data and reference assets stay in
ignored output directories.

The export pass now also covers 12 non-BGM pairs (battle, boss, card, confusion,
evolution, DNA evolution, and title banks), each with 16 sequence entries.
`MPCOMMON` needs a separate multi-entry export path. Exact matches do not validate
SPU playback, original instrument tuning, looping, tempo behavior, or reverb.
The [PSF authors' discussion](https://hcs64.com/mboard/forum.php?showpage=1&showthread=44576)
documents timing/reverb caveats, so reference audio duration is not used as an
identity test. The raw one-pass times in the catalog are not in-game cue lengths.
